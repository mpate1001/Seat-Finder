# Phase 3 — UI Design Contract

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Pin label letter-spacing, icon gap inside pin |
| sm | 8px | Overlay card internal padding (text rows), dismiss-button to viewport edge |
| md | 16px | Overlay card padding, top/side viewport margin for overlay card |

| xl | 32px | Reserved — not used in this phase |
| 2xl | 48px | Reserved — not used in this phase |
| 3xl | 64px | Reserved — not used in this phase |

**Tap-target exception:** Pin/dot markers are 44×44px footprint (Apple HIG minimum, see D-10/D-11) `[CONTEXT]`. Close button is 44×44px tap target with 32px visible glyph `[discretion, matches existing `floor-plan-close-button` 40px → bump to 44]`.

**Safe-area exception:** Close button and overlay card respect iOS safe-area insets via `env(safe-area-inset-top)` / `env(safe-area-inset-right)` so notch/Dynamic Island doesn't overlap them on iPhone `[discretion — required for "always full viewport" D-04]`.

## Typography

Exactly **2 font weights** declared: 400 (regular body) + 700 (bold for everything emphatic).

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Body | 14px | 400 | 1.5 | Overlay card description (`{guest.description}`) |
| Label | 12px | 700 | 1.0 | Neighbor table number labels (adaptive, fade in at ≥ 1.8×) |
| Heading | 16px | 700 | 1.3 | Overlay card greeting line (`Welcome, {firstName}! — Table {N}`) |
| Display | 14px | 700 | 1.0 | Number inside the assigned red pin (white, centered) |

**Mobile (`max-width: 600px`)** — same scale; the system font's optical sizes already render well at these px values, no breakpoint shrinking needed.

**Why these choices:**
- Hierarchy between greeting (16px), description (14px), pin number (14px white on red), and neighbor labels (12px) is achieved through **size and color**, not weight — so the contract collapses cleanly to two weights (400 body + 700 emphatic).
- Overlay must be **non-intrusive** (D-02), so the heading is 16px not 1.8rem like the old TableModal greeting. The map is the hero.
- Pin number (Display 14px @ 700) must read at a glance against the red fill — bold + tight line-height.
- Neighbor labels (12px @ 700) are intentionally small so they don't compete with the assigned pin's number; weight 700 keeps them legible at the small size against a busy floor plan.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` | Floor plan image background (the map image itself dominates the viewport) |
| Secondary (30%) | `#2b2d42` (dark navy, 90% alpha → `rgba(43, 45, 66, 0.9)`) | Overlay card background — lets a sliver of map peek through, keeps card readable |
| Accent (10%) | `#d90429` (red) | Assigned table pin fill ONLY |
| Muted | `#8d99ae` (slate) | All non-assigned table dots; neighbor labels (when shown) |
| Destructive | not applicable | No destructive actions in this phase |

**Accent reserved for** (explicit list — checker enforces):
1. The single assigned-table pin's teardrop fill (`#d90429`)
2. The pin's pulse ring (`#d90429` at decaying alpha, 1.2s cycle)
3. Nothing else. The close `×` button is white-on-translucent-dark (NOT red). The overlay card greeting text is white (NOT red).

**Why 60/30/10 maps this way:** The floor plan image IS the dominant surface — a guest spends most of their time looking at it. The overlay card is the secondary surface (top of viewport, ~10–15% of screen height). The single red pin is the accent — it pops because nothing else competes. 53 muted slate dots recede into the floor plan.

**Overlay card text colors:**
- Greeting line: `#ffffff` on `rgba(43, 45, 66, 0.9)` — passes WCAG AA at 16px/700 `[discretion]`
- Description line: `#edf2f4` (light gray) on same background — slightly de-emphasized to keep the greeting primary `[discretion]`

**Close button:**
- Background: `rgba(43, 45, 66, 0.7)` (matches overlay card family)
- Glyph: `#ffffff`
- Hover/active: background → `rgba(43, 45, 66, 0.95)`, no color shift

**Map backdrop (behind floor plan image):**
- `#000000` — true black so the map "floats" full-bleed and the image's white background reads cleanly as a paper map `[discretion]`

## Copywriting Contract

| Element | Copy |
|---------|------|
| Overlay card — greeting (heading) | `Welcome, {firstName}! — Table {N}` `[CONTEXT D-02]` |
| Overlay card — description (body, conditional) | `{guest.description}` (rendered only if non-empty) `[CONTEXT D-02]` |
| Close button — visible label | `×` (HTML entity `&times;`) `[CONTEXT D-03; matches existing TableModal pattern]` |
| Close button — `aria-label` | `Close map` `[discretion — accessibility requirement]` |
| Close button — `title` (tooltip on desktop) | `Close map (Esc)` `[discretion]` |
| Fallback when `tableNumber` not in `floorPlan.json` | `Table {N} — please ask staff for directions` `[CONTEXT `<specifics>`]` |
| Fallback layout | Overlay card stays; map shows overview with no pin; muted dots still visible. No animation runs. |
| Empty state heading | not applicable — map only opens after a guest is selected, so there is no empty state |
| Empty state body | not applicable |
| Error state | not applicable — no async fetch happens inside the map view (image is preloaded at app mount, D-15) |
| Destructive confirmation | not applicable — no destructive actions in this phase |
| First-open hint | **OMITTED** `[discretion within D-claude-discretion]`. Rationale: the overview → zoom-in animation is self-explanatory ("the map zoomed to my table"); pinch-to-zoom is muscle memory on mobile; the visible `×` is unambiguous. Adding a dismissable toast would clutter the hero moment. Reconsider in UAT only if testers struggle. |

**Copy invariants the executor must preserve:**
- Em-dash separator (` — `, U+2014 with surrounding spaces), not hyphen, between greeting and table number.
- No exclamation point on the table number (`Table {N}` not `Table {N}!`) — one exclamation on the greeting is enough.
- `firstName` rendered exactly as it arrives from CSV, no title-casing transformation.

## Visual Components

This section is non-template — added because Phase 3 introduces several new visual primitives that need precise specification before the executor can build them. Checker should treat these as PASS criteria for Dimension 2 (Visuals).

### Assigned-table pin (red teardrop)

| Property | Value |
|----------|-------|
| Shape | Teardrop / map pin — circular head with a downward point. Reference: classic Google Maps marker silhouette. |
| Implementation | Inline SVG inside a 44×44 positioned `<div>`. Anchor point = bottom tip of teardrop, NOT center, so the tip lands exactly on the table coordinate. |
| Fill | `#d90429` |
| Stroke | `#ffffff` 2px (gives definition over busy floor plan backgrounds) |
| Drop shadow | `filter: drop-shadow(0 2px 4px rgba(0,0,0,0.35))` |
| Inner number | `{tableNumber}` in `#ffffff`, weight 700, 14px, centered in the circular head (not the tip) |
| Tap target | 44×44px hitbox `[CONTEXT D-10]` (visual teardrop is ~36×44; transparent padding fills the rest) |
| Pulse | A second SVG circle behind the pin head, same fill, animated `keyframes pin-pulse`: scale 1.0 → 1.15 → 1.0 over 1.2s, opacity 0.6 → 0.0 → 0.6, infinite, `ease-in-out` `[CONTEXT `<specifics>`; discretion on exact curve]` |
| Pulse motion-reduction | When `prefers-reduced-motion: reduce`, pulse animation is disabled (pin renders static) `[discretion — a11y default]` |

### Non-assigned table dots (muted slate)

| Property | Value |
|----------|-------|
| Shape | Filled circle, 12px diameter |
| Fill | `#8d99ae` `[CONTEXT D-11]` |
| Stroke | `#ffffff` 1px (separation from floor plan lines) |
| Drop shadow | none (intentionally flat — they recede) |
| Tap target | 44×44px transparent hitbox around the 12px visual `[CONTEXT D-11]` (footprint, not visual size) |
| Label visibility | Hidden by default; fades in when `transformState.scale ≥ 1.8` `[discretion within D-09]` |
| Label style | 12px, weight 700, color `#2b2d42`, white outline (`text-shadow: 0 0 3px #fff, 0 0 3px #fff`) for legibility over floor plan, positioned 16px below the dot center |
| Pointer events | `pointer-events: none` `[CONTEXT D-12 — markers are visual only this phase]` |

### Overlay card (top-pinned)

| Property | Value |
|----------|-------|
| Position | `position: fixed; top: max(16px, env(safe-area-inset-top)); left: 16px; right: 16px;` |
| Max width | 480px on tablet+, centered (`margin: 0 auto`) |
| Background | `rgba(43, 45, 66, 0.9)` with `backdrop-filter: blur(8px)` (graceful fallback: solid `#2b2d42` when blur unsupported) |
| Border radius | 10px `[CLAUDE.md]` |
| Padding | 16px horizontal, 12px vertical (description present) or 8px vertical (greeting only) |
| Shadow | `0 4px 20px rgba(0, 0, 0, 0.35)` |
| Z-index | 100 (above the pan/zoom surface, below the close button at 110) |
| Animation in | `fadeIn` 0.3s + 8px slide-down (reuse existing `fadeIn` keyframe + new `slide-down`) |
| Pointer events | `pointer-events: none` on container, `pointer-events: auto` on inner content — so the user can pan/pinch through the card's transparent margin areas |
| Non-overlap guarantee | Overlay card's bottom edge must not overlap the assigned pin at the final zoom level. Library's `zoomToElement` automatically biases the centerpoint to satisfy this `[CONTEXT `<specifics>`]`. Executor adds a 64px top-bias offset in `zoomToElement` config to be safe. |

### Close button

| Property | Value |
|----------|-------|
| Position | `position: fixed; top: max(16px, env(safe-area-inset-top)); right: max(16px, env(safe-area-inset-right));` |
| Size | 44×44px tap target, 32×32px visible circle |
| Background | `rgba(43, 45, 66, 0.7)`, hover `rgba(43, 45, 66, 0.95)` |
| Glyph | `&times;` (×), `#ffffff`, 24px |
| Border radius | 50% `[CLAUDE.md]` |
| Z-index | 110 (above overlay card) |
| Keyboard | Escape key closes (reuse pattern from `TableModal.tsx` lines 13–22) |

### Map surface (pan/zoom container)

| Property | Value |
|----------|-------|
| Background | `#000000` (full-bleed black behind the floor plan image) |
| Position | `position: fixed; inset: 0;` |
| Z-index | 50 |
| `touch-action` | `none` `[CONTEXT D-17]` |
| `overscroll-behavior` | `contain` on the parent overlay `[CONTEXT D-17]` |
| Library | `react-zoom-pan-pinch` `<TransformWrapper>` + `<TransformComponent>` `[CONTEXT D-05]` |
| Initial state | `scale: fit-to-viewport` (computed from image natural size vs. viewport), centered. The wrapper waits for `<img onLoad>` before computing. |
| Pulse-then-zoom sequence | (1) Render at fit-to-viewport with assigned pin already pulsing. (2) Hold 250ms `[CONTEXT D-06]`. (3) Call `zoomToElement(assignedPinId, 2.75, 700, 'cubic-bezier(0.22, 1, 0.36, 1)')` `[CONTEXT D-06/D-07; discretion: scale=2.75, easing=ease-out-quart-ish]`. |
| Manual zoom bounds | `minScale: 1.0`, `maxScale: 6.0` `[discretion within D-08]`. Min = fit-to-viewport (can't zoom out further; nothing useful below it). Max = 6× (text on the floor plan stays sharp on retina at this scale). |
| Wheel zoom | enabled with `wheel.step: 0.2` (desktop) |
| Double-tap zoom | enabled, `doubleClick.mode: 'toggle'` (toggles between current scale and 2.75× on the tap point) |
| Reduced motion | When `prefers-reduced-motion: reduce`, skip the 700ms zoom-in animation: jump directly to the final transform with no easing. The pulse (already covered above) is also disabled. `[discretion — a11y default]` |

### Image loading (`<picture>` + preload)

| Property | Value |
|----------|-------|
| Source asset | `src/assets/Reception Seat Diagram.png` (unchanged) `[CONTEXT D-16]` |
| Variants generated | 900px / 1600px / 2400px wide, in AVIF + WebP + PNG = 9 files total `[CONTEXT D-13/D-14]` |
| Markup | `<picture>` with `<source type="image/avif" srcset="...900w, ...1600w, ...2400w" sizes="100vw">` + same for `image/webp` + `<img src="...png-fallback-1600.png">` `[CONTEXT D-13]` |
| `sizes` attribute | `100vw` (full viewport on every device) |
| Preload on app mount | `<link rel="preload" as="image" type="image/avif" href={avif1600} imageSrcSet="...900w, ...1600w, ...2400w" imageSizes="100vw">` injected into `<head>` from `App.tsx` startup, plus a hidden `<img>` with the same AVIF source as belt-and-suspenders `[CONTEXT D-15 + `<specifics>`]` |
| Decoding | `decoding="async"` on the `<img>` |
| `loading` attribute | `loading="eager"` (we want it ready before user selects a guest, not lazy-loaded) |

## Animations & Motion

| Animation | Duration | Easing | Trigger |
|-----------|----------|--------|---------|
| `fadeIn` (overlay card, close button, map surface) | 300ms | `ease` | MapView mount |
| Slide-down (overlay card 8px) | 300ms | `cubic-bezier(0.22, 1, 0.36, 1)` | MapView mount |
| `pin-pulse` (assigned pin glow) | 1200ms cycle | `ease-in-out` infinite | Pin render |
| Overview hold (no animation) | 250ms `[CONTEXT D-06]` | n/a | After image loads |
| Zoom-in to assigned table | 700ms `[CONTEXT D-06]` | `cubic-bezier(0.22, 1, 0.36, 1)` `[discretion]` | After overview hold |
| Neighbor label fade-in | 200ms | `ease` | When `transformState.scale` crosses 1.8× threshold (debounced) |
| Close button hover | 200ms | `ease` | Pointer hover |

**Reduced-motion override:** When `@media (prefers-reduced-motion: reduce)` matches, all animations above except `fadeIn` (kept short) reduce to instant transitions or are disabled. Specifically: pulse off, zoom-in becomes an instant transform jump, label fade is instant. `[discretion — WCAG 2.1 SC 2.3.3]`

## Interaction Contract

| Trigger | Result |
|---------|--------|
| Guest selected from search dropdown | `App.tsx` sets `selectedGuest`; `<MapView guest={...} onClose={closeModal} />` mounts |
| Map mounts | (1) Render fit-to-viewport with pin pulsing. (2) 250ms hold. (3) 700ms zoom-in to 2.75× on assigned pin. |
| User pinches/pans | Library handles transform; gestures live the entire time the map is mounted (D-08) |
| User scrolls scroll wheel on map | Zoom in/out around cursor (desktop) |
| User double-taps a point | Zoom in/out around tap point (toggle mode) |
| User taps a non-assigned dot | Nothing — dots are visual only `[CONTEXT D-12]` |
| User taps `×` button | `onClose()` → `App.tsx` clears `selectedGuest` → MapView unmounts |
| User presses Escape | Same as tapping `×` |
| User presses browser/hardware Back | Same as tapping `×` `[CONTEXT D-03]` (executor wires `popstate` listener; pushes a history entry on map open) |
| User taps overlay card | No-op (card has `pointer-events: auto` to prevent gesture pass-through but no click handler) |
| User selects a different guest while map is open | Map smoothly transitions: re-runs the overview-hold-zoom-in sequence for the new pin (handled by re-keying the wrapper or imperative `setTransform` + `zoomToElement` call) |
